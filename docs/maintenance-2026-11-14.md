# 维护报告：压缩盆栽植物判定边界、掉落防御与双端网络同步修复（2026-11-14）

## 一、 缺陷背景与场景溯源

在压缩模组（`compressedblocks`）与压缩拓展模组（`compressedblockspot`）的联动场景中，特别是将压缩漏斗盆栽放置在储物抽屉（Storage Drawers）上方时，发现了以下连锁问题：
1. **网络同步缺失**：使用压缩泥土右键压缩盆栽，盆内呈现空盆假象，但实测土壤已放入；
2. **植物判定越界**：再次右键压缩泥土，压缩泥土竟被识别为植物种入盆栽；
3. **掉落异常繁衍**：植物成熟收割时按甘蔗倍率（2~4倍）加上本体额外产出，源源不断向下方抽屉输送压缩泥土，造成严重的复制刷物漏洞；
4. **视线裁切过度**：在抽屉上方（1格高）仰视盆栽时，渲染器过于粗暴的相机判定导致盆内土壤被暴力剔除并闪烁消失。

## 二、 修复方案与逻辑边界

1. **物质分类与白名单机制**：
   - 彻底废除 `CompressedPotsAddon.levelOf(def) > 0` 判定；
   - 在 `SpotPotBlock` 中建立严密的植物白名单（仅放行原版作物/树苗/甘蔗及压缩作物/树苗/甘蔗），严禁任何无机压缩材料（泥土、圆石、矿石块等）作为植物种入；
   - 在 `soilLevelOf` 中加入植物拦截，杜绝植物误作土壤。
2. **掉落物安全防御**：
   - 在 `SpotPotBlockEntity.drops` 中独立分离甘蔗产出分支；
   - 增加防御性保底机制：对任何未预期的异常植物状态，仅掉落 1 份本体保底，彻底杜绝刷物隐患。
3. **C/S 双端数据包即时同步**：
   - 在 `SpotPotBlockEntity` 中封装 `sync()` 方法并在状态修改时调用 `server.sendBlockUpdated`；
   - 覆写 `getUpdatePacket()`（`ClientboundBlockEntityDataPacket`）与 `getUpdateTag()`；
   - 确保填土、播种、拔出、收获时客户端毫秒级渲染更新。
4. **高位视线渲染优化**：
   - 优化 `SpotPotRenderer` 的 `isSoilVisible` 几何判定，放宽合理的平视与仰视视距，消除高处摆放时的泥土闪烁与隐形缺陷。
5. **外部容器与抽屉对接守恒**：
   - `insertIntoBelow` 与 `ITEM_SINK` 逻辑完全零改动，容器自主仲裁，绝不越界修改外部逻辑。
