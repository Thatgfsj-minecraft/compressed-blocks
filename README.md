# Compressed Blocks（压缩方块）

把常见方块 3×3 压缩成 1~9 重，方便携带；压缩方块和压缩木棍可以做成工具，**耐久按 9ⁿ 指数上升、挖掘速度逐重提升，六重及以上直接不可破坏**。0.3.0 新增压缩护甲、农业系统（压缩耕地/作物/树苗/树叶）与压缩食物。

Thatgfsj-minecraft 组织出品，开发约定见 [mc-mod-dev-skill](https://github.com/Thatgfsj-minecraft/mc-mod-dev-skill)。

## 特性

- **459 种压缩储存方块**（51 材料 × 1~9 重）：
  - 石族：圆石、石头、深板岩圆石、深板岩
  - 原木：橡木/云杉/白桦/丛林/金合欢/深色橡木/红树/樱花/苍白橡木
  - 常见：泥土、沙子、沙砾、下界岩、末地石、黑曜石
  - 矿物块 8 种：煤炭/铜/铁/青金石/金/红石/绿宝石/钻石
  - 0.3.0 新建材 24 种：花岗岩/闪长岩/安山岩/方解石/凝灰岩/砂岩/红砂岩/玄武岩/黑石/钟乳石/陶瓦/石英块/紫珀块/海晶石/紫水晶块/荧石（发光 15）/黏土块/干草块/骨块/苔藓块/雪块/蓝冰/火药块/泥巴
  - **硬度 = 从原版硬度逐重线性升到 9 重目标**：1 重 = 原版硬度；9 重目标 = 黑曜石 200、原版硬度 ≥1.5 的硬类 150、软类 100（如圆石 2→150、泥土 0.5→100）；**全部 1200 爆炸抗性（炸不毁）**
- **9 重压缩木棍**：9 木棍 → 压缩木棍 → 二重压缩木棍 → …
- **90 件压缩工具（两条线）**：压缩圆石工具（圆石+深板岩圆石可混用）、压缩木质工具（9 种原木可混用）× 镐/斧/锹/锄/剑 × 9 重
  - **耐久 = 9ⁿ × 基础**（石 131 / 木 59）；**六重起不可破坏**
  - **挖掘速度（两条线分开）**：石线逐级连乘 ×1.5 —— 一重 6.0（铁镐）、二重 8.0（钻镐）、三重 12.0（金镐）、四重 18 → 九重 136.7；木线 = 石线 × 0.95 —— 一重 5.7 → 九重 129.85（仍远快于原版木镐的 2.0）；剑不参与（保持原版）
  - **挖掘速度对所有方块生效**：非本工具类别的方块（例如压缩木镐挖木质半砖/楼梯/木板、压缩斧挖石头）也至少按本档速度挖，不再回落到原版的 1.0；**掉落与挖掘等级仍按原版语义**（只有正确工具 + 足够等级才掉落，非正确工具的方块仍吃原版 3.33 倍挖掘进度惩罚）；剑保持原版、不参与挖掘速度
  - **攻击伤害 = 对应原版工具总伤害 × 1.6^重**（含玩家基础 1 点，逐重 ×1.6 指数成长；石线的材料加成按原版石质 +1 计入，剑同样参与）；**挖掘等级也按线分开**：石线 1~6 重=石级、7 重=铁、8 重=钻石、9 重=下界合金；木线 = 原版木工具的压缩版，整体比石线低一级 —— 1~6 重=木级、7 重=石级、8 重=铁级、9 重=钻石级（即木线 7 重才能挖铁矿、8 重才能挖金矿/钻石矿、9 重才能挖黑曜石；远古残骸在原版属钻石级，故两条线九重都能挖）；**九重工具（两条线均可）可挖基岩且基岩会掉落**
  - 附魔能力 = 原版石级/木级；铁砧修复 = 同重数的混用组（圆石线=圆石+深板岩圆石，木线=任一原木）
- **72 件压缩护甲**（石制 36 + 木质 36，各 4 部位 × 9 重）
  - 基准铁级（头 2/胸 6/腿 5/靴 2），每重每件 +1，**单件防御封顶 10，溢出部分直接丢弃（不再转抗性提升）**
  - 耐久 = 9ⁿ × 铁甲基准，六重起不可破坏；附魔能力 9，修复材料 = 同重数压缩石头（木甲 = 同重数 9 种压缩原木）
  - **四件全九重石甲 = 免疫一切伤害（含 /kill、虚空）+ 饱食度/饱和度常满**；木质盔甲按有效重数（重数-1）结算效果
- **农业系统**
  - **压缩耕地**（9 级）：锄 N 级压缩泥土需要 **N 级或以上**压缩锄头；无踩踏退化；挖掉掉回同重数压缩泥土
  - **压缩作物**（小麦/胡萝卜/马铃薯/甜菜根 × 3 级）：只能种在**等级足够**的压缩耕地上，种错会有彩色英文提示
  - 压缩小麦不可合成，只能靠**压缩种子**种出来（收获=压缩小麦+压缩种子，出货量结构同原版）；9 干草块 = 二重压缩小麦（原版 9 麦=干草块）；西瓜同理走西瓜块
  - **压缩树苗**（9 树种 × 9 重）：种在等级足够的压缩泥土上；**树形与原版一致**（含巨型云杉/巨型丛林/深色橡木 2×2 规则），树干树叶 = 同重数压缩方块；压缩树叶走原版凋落算法，掉落 5%+时运的压缩树苗
- **压缩食物**（19 种 × 3 级 = 57 件）
  - 19 种：面包、生/熟牛肉、生/熟猪排、生/熟羊肉、生/熟鸡肉、生/熟兔肉、生/熟鳕鱼、生/熟鲑鱼、西瓜、腐肉、烤土豆、苹果
  - 数值 = 原版 × 9^重；canAlwaysEat（饱了也能吃，金苹果式）
  - **营养溢出 → 主动回血**：溢出 ≤200 → 生命恢复 I × 溢出秒；200 < 溢出 ≤1000 → 生命恢复 II × (溢出-200) 秒；>1000 → 固定 生命恢复 V + 力量 V 各 600 秒（10 分钟封顶，不再随溢出增长）
  - 另有 6 件可食用的压缩作物（压缩胡萝卜/压缩马铃薯 × 3 级）复用同一套溢出规则，可食用物品合计 63 件
- 合成：3×3 压缩（9→1）、无序解压（1→9）、工具/盔甲按原版排列
- 创造物品栏：三个分类栏（压缩方块 / 压缩工具 / 压缩食物；压缩盆栽栏由附属 mod 独有）
- **压缩盆栽**（普通/漏斗盆栽，Botany Pots 机制）：盆内右键填压缩泥土/沙子（原版泥土/沙子记 1 级）→ 种原版作物/树苗/甘蔗（压缩植物需附属 mod 的压缩盆栽）→ 盆内渲染随生长从 40% 缩放到 100% → 30 秒一茬（土壤每比植物高 1 级提速 5%）→ 右键收割**自动补种**（作物按定稿产量表并吃压缩土壤概率翻倍，压缩作物走自身战利品表含时运；树苗 = 同重数原木 3~8 + 树苗 0~3）。漏斗盆栽成熟自动收割并优先塞进下方容器，全自动化。**原生兼容 FTB Ultimine（连锁破坏）**：按住热键右键即可一键连锁收获所有成熟盆栽并汇聚掉落物。
- **压缩甘蔗全材料化**：51 种储存材料各一条甘蔗线（钻石/煤炭/铁/火药/骨块……）+ 纯甘蔗，材料的 1x = 8 个一重压缩甘蔗 + 1 个对应材料的一重压缩方块居中（纯甘蔗线为 9 甘蔗 → 1 个一重压缩甘蔗），之后 9 个升级、分解返同级压缩方块；只能种在 N 重以上压缩泥土/沙子，生长同原版
- **四阶压缩熔炉系统**（1~4 重）：
  - 1重（`1x_compressed_furnace`）：整机速度 **6x**（3 路 × 单路 2x，每件耗时 ~1.67s），阶梯权限：可烧原版 + 1~3 重压缩方块/物品；

  - 4重（`4x_compressed_furnace`）：整机速度 **243x**（9 路 × 单路 27x，每件耗时 ~0.04s），可烧全量物品；
  - **挖掘**：任意等级镐（含木镐）即可挖掉并掉落本体（与原版熔炉一致；仍需要镐，空手/错工具不掉落）；

  - **可燃物**：压缩木制物品可作燃料（原版熔炉与压缩熔炉共用同一份燃料表）：压缩原木 300×(5^N)、压缩树苗 100×(5^N)、压缩木棍 100×(5^N)、木线工具与木制盔甲 200×(5^N)、木质漏斗 300×(5^N)（基础木漏斗 300）、压缩箱子 1500 tick，其中 N = 压缩重数（1~9）；**压缩盆栽（pot / hopper_pot）不可燃**。

## 数量核算（每个子项目）

1326 方块 = 459 储存（51 材料 × 9 重）+ 81 树叶（9 树种 × 9）+ 81 树苗（9 树种 × 9）+ 9 耕地 + 12 作物（4 种 × 3 级）+ 468 甘蔗（52 条线 × 9）+ 2 盆栽 + 198 压缩金属（22 材质 × 9）+ 3 刷石机 + 4 压缩熔炉 + 3 压缩漏斗 + 4 木质漏斗 + 1 压缩箱 + 1 压缩潜影盒
1563 物品 = 1317 方块物品（1326 方块去掉 9 个无物品的压缩耕地；含 12 件作物种子/作物物品与 468 件甘蔗）+ 90 工具 + 72 盔甲（石/木各 36）+ 9 压缩木棍 + 6 作物产物（压缩小麦/压缩甜菜根）+ 57 食物（19 种 × 3）+ 12 额外种子（南瓜/西瓜/火把花/瓶子草 × 3）｜126 树特征｜双语语言文件

核算方法：按 `CompressedContent.init()` 各注册循环的条数逐项累加；`assets/compressedblocks/blockstates/` 目录文件数 = 1326，与方块总数交叉验证；`CompressedSelfTest` 硬断言 1326 方块 / 1563 物品，E2E 启动日志的 `SELF-TEST PASS` 会打印实际注册数。

## 资源生成

仓库里的贴图与全部 JSON 资源都由 `scripts/` 下的生成器产出。**四步流水线顺序敏感**，一键入口：

```bash
./scripts/gen_all.sh              # 在仓库任意位置执行
./scripts/gen_all.sh --target 1.21.11   # 额外参数透传给 gen_resources.py
```

| 步骤 | 脚本 | 产物 |
| --- | --- | --- |
| 1 | `scripts/gen_assets.py` | `assets/compressedblocks/textures/**` 全部贴图（方块 / 物品 / 盔甲 / 实体 / 容器 GUI） |
| 2 | `scripts/gen_resources.py` | blockstate、方块与物品模型、`items/` 物品模型定义、配方、战利品表、标签、双语语言、装备资产 |
| 3 | `scripts/gen_hopper_assets.py` | 1~3 重压缩铁漏斗：贴图、模型、blockstate、items、配方、语言与标签条目 |
| 4 | `scripts/gen_wooden_hopper_assets.py` | 木质漏斗 + 1~3 重压缩木质漏斗：同上，另含战利品表 |

- **第 2 步按资源域拆分**：`scripts/gen_resources.py` 只保留 CLI、清单断言、清理调度与逐 loader 循环；共享常量/名称 helper/写出工具/所有权清理在 `scripts/res_common.py`，资产生成在 `res_assets.py`，语言在 `res_lang.py`，数据（配方/战利品表/标签/树特征）在 `res_data.py`。拆分不改变任何生成结果。

- **为什么不能跳步**：第 2 步会清空它自己拥有的生成目录（`assets/compressedblocks` 下除 `textures/` 与本脚本保留白名单之外，以及 `data/` 下 `compressedblocks` / `minecraft` / `c` / `ftbultimine` 四个命名空间），第 3、4 步再把漏斗的资产、配方、战利品表、语言与标签条目补回去。只跑前两步会让漏斗资源丢失——这正是 `gen_all.sh` 存在的理由。
- **幂等验收**：跑完 `git status --short` 必须为空。生成器只写真正变化的内容（贴图逐像素比较；清理只碰自己的产物），重跑不会制造无意义 diff。若出现 diff，说明生成器与仓库内容不同步：改生成器，不要手改生成出来的文件。
- **不要手工编辑**生成目录中的文件——除两个手写模型模板 `assets/compressedblocks/models/block/template_hopper.json` 与 `template_hopper_side.json`（`gen_resources.py` 的保留白名单会保住它们）之外，其余文件下次生成即被覆盖。
- **loader 专属文件**：`data/neoforge/data_maps/item/furnace_fuels.json`（燃料数据图）不归生成器所有，既不生成、也不会被清理。
- **依赖**：Python 3 + Pillow + numpy。贴图基元缓存在 `_asset-src/vanilla/`、树特征模板在 `_asset-src/vanilla-data/`（均不入库）；漏斗贴图另需原版 jar（跑过一次 Gradle 构建后 Loom 缓存里就有，也可用环境变量 `MC_JAR` 指定）。
- **分级定义单一来源**：`scripts/hopper_tiers.py`——漏斗 id 与中英文名由三个脚本共用，新增漏斗档位只改这里。
- 提交前自查：`./scripts/gen_all.sh && git status --short` 为空，即资源与生成器同步。「构建 / 测试」小节里那条只列前两个脚本的旧提示以本节为准。

## 构建 / 测试

```bash
cd 1.21.11/fabric   && GRADLE_USER_HOME=<干净目录> ./gradlew build
cd 1.21.11/neoforge && GRADLE_USER_HOME=<干净目录> ./gradlew build
# 产物：build/libs/compressedblocks-<loader>-<mc版本>-<version>.jar
```

- 环境：Loom 1.17.21 / ModDevGradle 2.0.147 / Gradle 9.5.1 / JDK 21（版本坐标在各子项目 gradle.properties）
- **GRADLE_USER_HOME 必须指向无 init.gradle 的干净目录**（全局阿里云镜像会破坏 NeoForge 解析）
- 贴图与全部 JSON 由脚本生成：`python scripts/gen_assets.py && python scripts/gen_resources.py`（原版 sprite 缓存于 `_asset-src/vanilla/`，树特征模板在 `_asset-src/vanilla-data/`，均不入库）
- **燃料数据图由 NeoForge datagen 生成**：改完 `CompressedFuels` 规则后执行 `cd 1.21.11/neoforge && ./gradlew runServerData`，产物写入 `src/generated/resources/data/neoforge/data_maps/item/furnace_fuels.json` 并入库；忘记重跑时 NeoForge 启动自检会直接报错。Fabric 端走 `FuelRegistryEvents`，同一份规则，无需生成文件
- **双端一致性检查**：`python scripts/check_parity.py`（比较 `src/main/resources/{assets,data}` 与共享 Java 源；`src/generated` 与加载器专属目录不参与）
- E2E：`ci/` 下的专用服 + RCON 断言（`node ci/e2e.js`，环境变量 `RCON_PORT` 指定端口），服务器启动日志搜 `SELF-TEST PASS`（服务端权威比对注册数/硬度公式/护甲属性/食物数值/标签族）

## 素材说明

全部贴图由 `scripts/gen_assets.py` 从**原版** sprite 程序化重绘，未复制任何第三方模组像素。压缩层视觉语言：底图灰色滤镜 + 外围压缩环封顶 5 圈（1~5 重黑/浅黑圈；6~8 重外围改深紫/浅紫圈；9 重最外圈白色细圈）；物品按同一配色逐级染色；盔甲 = 铁甲图层重着色为石质。
